# Подбор счётчиков воды — браузерная версия

То же самое, что настольная программа `WaterMeterSelection`, но в браузере и в
оформлении «Насосной лаборатории»: та же шапка с вкладками-таблетками, те же
цветовые переменные, светлая и тёмная тема по настройкам системы.

Вводится место установки, назначение системы и секундный расход — программа
подбирает калибр, показывает потери **сразу двумя методами**, вы выбираете
вариант, жмёте ОК, и строка ложится в таблицу подбора. Таблица выгружается в
Word с объединением ячеек по месту установки.

Всё считается в браузере. Интернет не нужен, ничего никуда не отправляется.

## Запуск

Двойной щелчок по `index.html` — этого достаточно: сборки нет, скрипты
подключены обычными `<script src>`.

Для отладки и проверки с планшета — локальный сервер:

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

Порт 8784 (`watermeter-web` в `.claude\launch.json`), адрес `http://localhost:8784/`.

Проверки расчёта и выгрузки — `tests.html`, 52 штуки: контрольная точка
паспорта, семь строк реальной таблицы подбора, автоподбор, формат чисел,
группировка, структура .docx и файл проекта.

## Как считаются потери

**По паспорту завода** (таблица 2 паспорта):

    ΔP = K · Q² · 10⁻⁴   [кгс/см²],  Q — расход, м³/ч
    h  = ΔP · 10          [м вод. ст.]

**По СП 30.13330 (СНиП 2.04.01-85*, прил. 4):**

    h = S · q²   [м],  q — расход, л/с

Пересчёт расхода: `Q [м³/ч] = q [л/с] · 3,6`.

Обе величины считаются одновременно и стоят рядом в списке вариантов.
Переключатель «Потери в таблицу принимать» решает, какая попадёт в таблицу;
при выборе СП примечание со ссылкой на норматив подставляется само.

Предельные потери напора (правятся в настройках): **крыльчатые — 5 м,
турбинные — 2,5 м.**

## Автоподбор

Рекомендуется **наименьший** калибр, проходящий одновременно по потерям и по
паспортному диапазону `Qmin … Qmax`. При типе «Авто» сначала перебираются
крыльчатые, затем турбинные.

Список показывает **все** калибры сразу, поэтому «взять на калибр больше» —
один щелчок. Так и задумано: автоподбор берёт минимальный проходящий, а живой
инженер нередко берёт следующий. Пример из реального проекта: при 1,95 л/с
автоподбор предлагает ВСХНд-32 (4,94 м — впритык к пределу 5 м), а в проекте
принят ВСХНд-40 (1,90 м).

## Файлы

```
index.html            страница целиком: разметка всех вкладок
tests.html            проверки, открыть и посмотреть на зелёное
serve.ps1             локальный сервер для отладки, порт 8784
css/app.css           оформление (переменные — из PumpLabWeb)
js/util.js            числа по-русски, разбор ввода, отдача файлов
js/tables.js          нормативные справочники — единственный файл с данными
js/calc.js            оба метода потерь и алгоритм подбора
js/rows.js            строка таблицы и группировка по месту установки
js/report.js          текст расчёта по каждой строке
js/docx.js            упаковщик zip и сборка .docx
js/project.js         настройки, файл .wms, автосохранение
js/ui.js              вкладки, форма, таблицы, кнопки
```

Справочники лежат прямо в `js/tables.js`, а не отдельными файлами данных:
по протоколу `file://` подтянуть их через `fetch` нельзя, CORS режет. Правятся
текстом, сборка не нужна.

## Общий формат проекта с настольной версией

Файл `.wms` — UTF-8, табуляция, числа с точкой; ключи в нём те же
(`Vane`/`Turbine`, `Cold`/`Hot`/`Circulation`/`Heat`, `Passport`/`Sp`).
Подбор, начатый в окне, открывается в браузере и наоборот. Это проверяется
в `tests.html`.

Текущая таблица, кроме того, сама запоминается в `localStorage`, так что
страница открывается там, где её закрыли.

## Выгрузка в Word

`.docx` собирается вручную: сначала zip (метод «без сжатия»), потом OOXML —
никаких внешних библиотек. Получается настоящий документ с рамками и
вертикальным объединением ячеек по месту установки, а не таблица из HTML.

Ошибка, которую здесь легко посадить и на которую есть проверка: размер
центрального каталога в записи EOCD нужно снимать **до** её записи, иначе он
оказывается на 12 байт больше и Word такой архив не принимает. Проверка
`«Центральный каталог zip читается так, как его читает Word»` читает архив
именно с конца — через EOCD и каталог, как это делает Word.

## Две особенности нормативных данных

- **DN 200 в таблице СП**: по СНиП там `3,5·10⁻⁵`. В ходовой Excel-табличке в
  этой ячейке часто продублировано значение DN 65 (`0,0081`) — это опечатка,
  программа берёт `0,000035`.
- **DN 125 в таблице СП отсутствует** — для него доступен только паспортный
  расчёт; в колонке «Потери по СП» стоит прочерк.
