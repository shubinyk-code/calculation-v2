# Расчёт стальных П-образных компенсаторов

Браузерная программа: удлинение участка — геометрия компенсатора — сила упругого
отпора и напряжения — нагрузки на неподвижные опоры и перекрытия — расстановка
по этажам — динамическая схема узла — выгрузка в PDF и DXF.

Открывается двойным щелчком по `index.html`. Сборки нет: обычные `<script src>`,
глобальные объекты, никаких зависимостей. Для отладки — `serve.ps1` (порт 8785,
конфигурация `compensator-web` в `..\.claude\launch.json`). Проверки — `tests.html`,
69 штук.

## Что считается

| Раздел | Что получается |
|---|---|
| Удлинение | α по температуре, Δl = α·L·Δt, холодная растяжка, расчётное перемещение Δ |
| Отводы | характеристика гиба h, коэффициент жёсткости (Кармана) k, коэффициент интенсификации m₁ |
| Упругий центр | приведённая длина оси Lпр, координата ys, момент инерции упругой линии Jxs |
| Усилия | сила упругого отпора Px, максимальный момент Mmax, напряжение σ, проверка по [σ] |
| Обратная задача | компенсирующая способность Δдоп, предельная длина участка Lmax, подбор вылета H |
| Нагрузки | Fv, Fhy, силы трения, концевая и промежуточная неподвижные опоры, нагрузка на перекрытие |
| Расстановка | число этажей на участок, количество опор и компенсаторов, шаг креплений стояка |

## Метод

Метод упругого центра тяжести — тот же, что в справочной литературе по тепловым
сетям (Громов/Шубин 1988, Соколов 1982, Николаев 1965) и, как частный случай,
в приложении 3 РД 10-400-01. Компенсатор — плоская рама, защемлённая по концам,
с заданным взаимным смещением концов Δ; задача решается теоремой Кастилиано,
оси переносятся в упругий центр, после чего

    Px = Δ · E · J / Jxs,   Mmax = Px · (H − ys),   σ = m₁ · Mmax / W.

Одно отличие от справочника: интегралы ∫y·ds и ∫y²·ds берутся аналитически по
участкам оси (спинка, четыре отвода, два вылета, два плеча), а не графически
«по миллиметровке», как предлагал Соколов. Результат от этого точнее.

## Сверка

Проверено по опубликованным числам статьи С. Б. Горуновича «Расчёт П-образных
компенсаторов» (РосТепло.ру, 2009):

* коэффициент жёсткости отводов — таблица № 1: 89×3,5 → 0,154; 159×6 → 0,154;
  325×10 → 0,134; 630×12 → 0,106. **Совпадение точное.**
* напряжения — таблица № 2 для четырёх компенсаторов 108×4 … 530×12:
  расхождение 1,8…2,6 %. Оно целиком приходится на коэффициент m₁, приведённый
  в статье округлённо («≈ 4,2» для 530×12).

Формула коэффициента жёсткости, восстановленная по этим четырём точкам:

    h = s·R / r²ср,   rср = (Dн − s)/2
    k = (1 + 12h²) / (10 + 12h²) ≤ 1

### Нормативная развилка

СП 124.13330.2012 п. 10.1 отсылает к РД 10-400-01, а сам РД с 01.01.2021 отменён
«регуляторной гильотиной» (ФЗ № 247-ФЗ). Действующий документ того же назначения —
ГОСТ Р 55596-2013; его разработчики (они же авторы РД) прямо рекомендуют считать
по нему — см. Магалиф В. Я. и др. // Новости теплоснабжения № 2 (218), 2019.
Программа считает по справочной методике, общей для обоих документов, и выводит
допускаемое напряжение тремя способами на выбор: по справочнику (160 / 120 МПа),
по табл. 2.1–2.2 РД 10-249-98 и вручную.

## Чего программа не делает

Это расчёт самого компенсатора и нагрузок от трубопровода, а не полный расчёт
трубопровода на прочность. Не учитываются: вес компенсатора как изгибающая
нагрузка, ветер, сейсмика, просадки, циклическая прочность (выносливость),
распор от внутреннего давления в осевых компенсаторах, защемление трубы в грунте
при бесканальной прокладке. Прочность опорной конструкции, закладной детали,
анкеров и перекрытия — задача конструктора: программа выдаёт ему усилие, а не
заключение о несущей способности.

## Грабли, на которые уже наступили

* **PDF и кириллица.** Векторный текст в PDF требует встроенного шрифта, а
  шрифтов в проекте нет. Поэтому страницы рисуются на canvas и кладутся в PDF
  картинками JPEG (DCTDecode) — текст не выделяется, зато файл собирается сам.
  Кнопка «Печать» даёт векторный вариант через «Сохранить как PDF» в браузере.
* **Цвета в схемах.** Они задаются атрибутами, а не классами CSS: при отрисовке
  SVG в canvas переменные `--ink` и прочие не разрешаются, и картинка выходит
  чёрно-белой.
* **Дуги в SVG.** Отводы рисуются ломаной из 18 отрезков, а не командой `A`:
  так схема одинаково верно строится и в «лежачей» ориентации, и в «стоячей»,
  без возни с флагами `sweep`. В DXF уходят настоящие `ARC`.
* **Подбор вылета.** Найденный делением пополам H округляется **вверх** до 10 мм,
  иначе после округления вниз напряжение оказывается на десятые доли выше
  допускаемого и программа сама себе пишет «не проходит».
* **Спинка, связанная с вылетом,** тоже округляется вверх до 10 мм: чертёжный
  размер должен быть круглым, а больший B только снижает напряжение.
